  * **Markdown 渲染引擎**：`MarkdownContent.vue` 实现三阶段管线：`sanitizeContent()`（innerHTML→textContent 循环最多 10 层，防嵌套 HTML 注入）→ `marked.parse()`（配置 GFM + `markedHighlight` + hljs 注册 13 种语言）→ `DOMPurify.sanitize()`（注册 hook 移除 `<span>` 标签仅保留 `<pre>` 内代码高亮 span）→ `requestAnimationFrame` 节流 DOM 更新。配套 hljs 自定义主题 `hljs-theme.css`（低饱和工业色调）。
  * **自动滚底与流式占位动画**：`MessageList.vue` 中通过 `isNearBottom()` 检测用户是否在底部（阈值 48px），仅在用户未主动上滚时自动 `scrollToBottom()`。`StreamingIndicator.vue` 实现三个脉冲圆点（staggered `animation-delay`）+ 当前节点名称显示。`LoaderCube.vue` 实现 3D CSS 立方体旋转 spinner。
  * **SessionDrawer 与会话管理**：`SessionDrawer.vue` 采用模态抽屉（overlay + macOS 卡片），`SessionItem.vue` 以终端风格（`$` 图标 + ID 前 8 位作 fallback 名称 + 日期 + hover 显示删除按钮）展示会话列表。`stores/session.js` 管理 `load/create/select/remove/clearAll/rename` 全部操作。
  * **空指针修复**：在 `stores/chat.js` 的 `send()` 方法中，若 `!targetSessionId` 则先调用 `sessionStore.create(userId)` 创建会话再发送消息，确保首条消息发送前 session 已存在。修复前表现为首条消息发送时 `sessionId` 为 null 导致后端报错。
  * **ThinkingSteps 组件**：`ThinkingSteps.vue` 实现两级展开（面板整体展开/收起 + 单步骤详情展开）。`nodeColor()` 将 planner→sky、agent→accent、action→blue、observation→green、compress→tertiary 映射不同语义色。支持 `tool\\\_calls` 参数和返回值展示。`ThinkingInline.vue` 提供 DeepSeek 风格的简洁内联 thinking 条（可展开 bullet list），过滤 `tool\\\_call\\\_start` 事件，将工具名映射为中文描述。

**四、 遇到的问题与困难**

* **技术问题：**

  * **SSE 流式传输中 Chrome 缓冲问题**：Chrome 对 `text/event-stream` 默认缓冲 512 字节，导致流式内容延迟到达。
  * **已尝试的解决方案：** 在 `vite.config.js` 代理配置中移除了 `accept-encoding` 头，并在后端响应头中设置 `Cache-Control: no-cache` 和 `X-Accel-Buffering: no`，强制禁用 nginx/浏览器缓冲。
  * **需要帮助或待解决：** 无。
  * **Markdown 渲染安全防护设计**：`marked` 输出的 HTML 若直接 `v-html` 渲染存在 XSS 风险；但 `DOMPurify` 会移除 `<code>` 内 hljs 生成的 `<span>` 高亮标记，导致语法高亮丢失。
  * **已尝试的解决方案：** 实现了 fence-aware 净化策略——在 `DOMPurify` 中添加自定义 hook，仅允许 `<pre>` 内的 `<span>` 通过，移除其他位置的 `<span>`，兼顾安全性和代码高亮效果。同时 `sanitizeContent()` 通过递归解码（最多 10 次循环）防止多层 HTML 实体绕过。
  * **需要帮助或待解决：** 无。
  * **auto-scroll 与用户阅读体验的冲突**：流式内容持续增长时，若强制每帧滚底会打断用户主动上滚查阅历史的行为。
  * **已尝试的解决方案：** 采用 `isPinnedToBottom` 模式——当用户主动上滚超过阈值 48px 时，暂停自动滚底；用户手动滚回底部后再恢复自动跟随。每次内容更新时通过 `scheduleScrollIfNeeded()` 依据 `isNearBottom()` 结果决定是否执行滚动。
  * **需要帮助或待解决：** 无。

**六、 心得体会与学习收获**

* **本周学习到的新知识/技能：**

  * 掌握了 `ReadableStream.getReader()` + AsyncGenerator 模式的 SSE 客户端实现，替代了传统的 `EventSource` API（`EventSource` 不支持 POST 和自定义 Header）。
  * 深入理解了 `DOMPurify` 的 hook 机制，实现了细粒度的 HTML 净化策略（区分代码块内外标签）。
  * 掌握了 CSS 自定义属性（design token）体系在暗色/亮色主题切换中的工程化实践——通过单个 `data-theme` 属性驱动全局样式切换，而非 CSS 变量逐个覆写。
  * 学习了 `marked` + `markedHighlight` 的集成方式和 hljs 语言注册机制。
  * 实践了 `requestAnimationFrame` 在流式内容渲染中的帧对齐节流，避免了 `setTimeout` 的无效重绘。
* **对项目或开发流程的思考：**

  * 前三项任务（工程搭建 → Bubble/Markdown → Session/状态管理）本质上是按数据流链路自底向上构建的：SSE 传输层 → 渲染展示层 → 会话管理层。这种分层递进的开发顺序符合前端架构的天然分层，每层完成后再叠加下一层，避免了同时改动多个不相关的模块。
  * 第四项（ThinkingSteps）作为 Agent 可解释性的入口，技术价值在于将后端 trace 数据转化为用户可感知的渐进式思考过程，而非简单的日志 dump。折叠卡片的层次设计（整体折叠 + 单步展开）平衡了信息密度和界面简洁性。
* **自我改进方面：**

  * 后续开发中应更早介入错误处理（如 SSE 连接中断重连、流式传输超时兜底），而非仅在 happy path 完成后再补充。
  * 组件拆分粒度可进一步优化——`ChatBubble.vue` 内 thinking 折叠状态机逻辑较重，可考虑抽取为独立 composable 供 `ChatBubble` 和 `ToolBubble` 复用。
