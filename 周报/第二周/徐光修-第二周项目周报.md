**二、 本周完成工作**

*   **目标达成情况：**
    1. 知识库文件树服务：已完成 100%
    2. 文件变更实时监听与推送：已完成 100%
    3. 知识库三路联合搜索：已完成 100%
    4. 知识图谱可视化与画布渲染：已完成 100%
    5. 知识库文件管理系统（CRUD + 上传 + 路径安全）：已完成 100%

*   **具体完成任务列表：**
    *   **文件树服务：** 编写了知识库目录的递归文件树构建逻辑，设计了一个前端可以直接使用的树节点结构（包含文件名、路径、是否为文件夹、修改时间、大小等字段），文件夹排在文件前面、同级按名称排序。通过 REST 接口向外暴露，前端拿到后无需额外转换就能直接渲染。
    *   **文件变更实时监听：** 使用 watchdog 库对知识库目录做递归文件监听，当磁盘上新增、修改、删除文件时，通过 SSE 长连接实时推送给前端，触发文件树自动刷新。同时实现了一套基于目录签名轮询的兜底方案，在 watchdog 不可用的环境下也能正常工作，每隔 15 秒发一次心跳保活。
    *   **三路联合搜索：** 实现了一个聚合三种搜索方式的 REST 接口——文件名匹配（遍历文件树节点做模糊匹配）、全文内容搜索（先在向量索引里搜，搜不到的再直接扫描磁盘文件做字符串匹配，两路结果去重合并）、语义搜索（向量检索后按知识库归属过滤）。搜索结果会截取命中位置前后各 80 个字符作为片段展示。
    *   **磁盘兜底检索：** 实现了当向量索引没有命中时，直接遍历知识库目录下所有文本文件、逐文件按关键词做内容匹配的兜底方案。按后缀白名单过滤可识别的文件类型，遇到二进制文件或编码异常自动跳过，结果数设了上限防止大目录超时。
    *   **知识图谱可视化：** 后端提供文件树数据，前端将嵌套的文件树结构转换为扁平化的图谱模型（节点和连线），文件夹是圆形节点、文件是小圆点，按层级深度递减半径，父子关系用连线表示。图谱画布基于 Canvas 2D 实现：支持鼠标滚轮缩放（以鼠标位置为锚点）、拖拽平移、双击节点聚焦、拖拽节点重新布局。力导向布局采用分层策略，节点按深度预分布在同心环上，避免初始位置堆叠。做了 Retina 屏幕适配，在高 DPI 显示屏上不会模糊。
    *   **文件管理系统：** 实现了知识库文件的常规操作——读取、写入、创建、删除、重命名、复制、新建文件夹、上传文件。所有路径操作都做了防路径穿越处理，防止用户传入 `../../etc/passwd` 这样的恶意路径。还实现了目录签名机制，通过记录每个文件的修改时间、大小和类型来检测文件是否有变化，供事件流做变化判断。

**三、 未完成工作及原因**

*   **未完成任务列表：**
    *   图谱的实体抽取与文档内容级语义关系可视化：完成了文件树结构图谱，但文档内部的实体识别（命名实体、主题关联）尚未实现
    *   **原因：** 实体抽取需要集成 NLP 模型（如 spaCy 或基于 LLM 的抽取），当前阶段优先保证文件树图谱的基本浏览和力导向布局体验
    *   搜索性能优化：文件树构建在大目录下性能不够理想
    *   **原因：** 每遍历一个文件都单独调用了多次系统 stat 命令，2000 个文件就要调用几千次，已经定位到问题，后续切换成批量扫描接口优化

**四、 遇到的问题与困难**

*   **技术问题：**
    *   文件树构建时每遍历一个文件就单独获取一次文件信息，在大目录下产生大量系统调用，2000 个文件耗时约 3 秒
    *   **已尝试的解决方案：** 确认根因为 API 设计上无法一次 stat 复用，后续改用操作系统级别的批量扫描接口一次性获取全部元信息
    *   **需要帮助或待解决：** 无
    *   搜索时如果知识库混入了二进制文件（如图片、PDF），直接当做文本读取会崩溃
    *   **已尝试的解决方案：** 添加异常捕获跳过不可读的文件，同时加强后缀白名单过滤
    *   **需要帮助或待解决：** 无
    *   图谱画布在 Retina 屏幕（如 MacBook 外接 4K 显示器）上显示模糊
    *   **已尝试的解决方案：** 按设备像素比缩放画布实际分辨率，再通过坐标变换保证显示清晰
    *   **需要帮助或待解决：** 无
*   **非技术问题：**
    *   前端监听不到文件树数据的更新，图谱不会自动刷新
    *   **已采取的措施：** 父组件改为整体替换数据对象而不是修改属性，同时提供了一个手动刷新方法做兜底
    *   Windows 上路径大小写问题：Python 的路径包含判断是字符串比较，但 Windows 文件系统不区分大小写，导致路径穿越检测在某些情况下误判
    *   **已采取的措施：** 已统一做路径解析展开，后续考虑用跨平台的文件路径比较方法做兼容

**六、 心得体会与学习收获**

*   **本周学习到的新知识/技能：**
    *   watchdog 库的跨平台文件系统事件监听架构，以及 SSE 做实时推送的实践
    *   Canvas 2D 的视口变换设计模式——把屏幕坐标和世界坐标解耦，代码简洁且易于维护
    *   力导向布局的初始位置分布对最终布局质量的影响很大，预分布比随机起点效果好得多
    *   d3-force 的分层力模拟参数调优经验
*   **对项目或开发流程的思考：**
    *   "三路搜索"比单一方案鲁棒得多：文件名匹配最快但可能改名了找不到，全文搜索最全面但大目录慢，语义搜索能搜到字面不匹配但意思相近的内容。三路结果交给 LLM 综合判断，比依赖任何一种单路搜索都靠谱。
    *   文件管理看似简单的增删改查，安全隐患其实很多：路径穿越、上传文件名篡改、编码问题、竞争条件，每步都要谨慎。把路径校验抽成统一方法在六处复用，既省代码又防遗漏。
*   **自我改进方面：**
    *   后续在工具函数参数校验上加强边界测试，特别是搜索场景下的特殊字符处理和超长输入截断。
    *   对大目录性能问题应更早做性能分析，不要因为 Python 的便捷 API 而忽略了底层的系统调用开销。
