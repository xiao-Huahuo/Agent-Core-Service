  * **EditorWorkspace CSS Grid 六列响应式布局**：在 `EditorWorkspace.vue` 中构建 `grid-template-columns: 40px var(--file-col-width) var(--file-resizer-width) minmax(0, 1fr) var(--agent-resizer-width) var(--agent-col-width)` 六列网格布局。通过 CSS 自定义属性（`--file-col-width` / `--agent-col-width` 等）驱动列宽，实现拖拽调整面板大小时仅变更 computed style 属性，避免触发 Vue 响应式批量重渲染。移动端（≤760px）自动降级为三行堆叠布局（文件树 → 编辑器 → Agent），resize handle 在窄屏下自动隐藏。面板折叠/展开采用 `transition: grid-template-columns 180ms ease` 动画，折叠时面板设置 `pointer-events: none` + `opacity: 0` 防止隐藏面板接收交互事件。

  * **可拖拽面板分隔条（Resize Handle）**：实现 `startResize()` / `handleResizeMove()` / `stopResize()` 三个 PointerEvent 生命周期方法。拖拽开始时在 `window` 上注册 `pointermove` 和 `pointerup` 监听器（而非在 handle 元素上），确保鼠标移出 handle 区域后仍能持续跟踪位置。拖拽过程中通过 `clamp(value, MIN_PANEL_WIDTH, MAX_FILE_WIDTH)` 限制面板宽度范围。面板宽度低于 `COLLAPSE_THRESHOLD`（150px）时自动折叠，用户继续向外拖拽超过阈值时自动展开。拖拽期间通过 `.workspace-page.resizing` 类禁用 CSS transition（`transition: none`）和全局 `user-select: none`，避免动画延迟导致的视觉抖动。

  * **ActivityBar 视图切换器**：实现 `ActivityBar.vue` 作为左侧 40px 宽的垂直图标栏，承载 File（文件树）、Agent（智能助手）、Graph（知识图谱）、Dashboard（仪表盘）、Search（搜索）、Settings（设置）六个视图入口。每个图标按钮通过 `@toggle-file` / `@toggle-agent` / `@toggle-graph` 等事件向父组件通知切换意图，父组件通过 `workspaceStore.setMainView()` 统一管理当前活跃视图。知识图谱和仪表盘使用 `defineAsyncComponent` 懒加载，减少首屏打包体积。

  * **递归文件树组件（TreeNode.vue）**：实现递归组件 `TreeNode`，每个节点包含展开/折叠箭头（`ChevronDown` / `ChevronRight`）、文件类型图标和名称文本。文件类型分类体系覆盖 7 种类别——Markdown（`file-kind-markdown`，紫色高亮）、Web 前端代码（`file-kind-web`，金黄色，覆盖 js/jsx/ts/tsx/vue/html/css/scss）、后端代码（`file-kind-code`，紫色，覆盖 py/go/rs/java）、数据文件（`file-kind-data`，蓝色，覆盖 json/yaml/xml）、图片（`file-kind-image`，绿色）、表格（`file-kind-sheet`，绿色系）、压缩包（`file-kind-archive`，棕褐色）。选中行通过 `::before` 伪元素渲染左侧渐变光带 + `tree-selection-slide` 入场动画。

  * **文件树拖拽系统**：实现自定义 MIME 类型 `application/x-metaweave-tree-paths` 的树内拖拽。`dragstart` 时通过 `event.dataTransfer.setData()` 写入 JSON 序列化的路径数组；`drop` 时优先检查 `event.dataTransfer.files`（外部文件拖入），其次读取自定义 MIME 数据（树内节点移动）。拖拽悬停时通过 `dragOver` 响应式变量切换 `.drag-over` 类（蓝色边框 + 半透明背景），`dragleave` 时通过 `relatedTarget` 对比防止子元素冒泡导致的误触发。全流程在 TreeNode 内部闭环，通过事件冒泡向 FileTreePanel 传递 `dropFiles` / `dropNodes` 语义事件。

  * **文件树内联编辑（insertDraftNode 虚拟节点模式）**：在 `FileTreePanel.vue` 中实现内联重命名和新建文件/文件夹功能。新建操作不直接修改文件树数据源，而是向树中插入一个 `insertDraftNode` 虚拟节点（`isDir` 由操作类型决定，`path` 以 `__draft__` 前缀标记），虚拟节点渲染为内联 `<input>` 而非普通文本标签。提交时通过 `editCommit` 事件调用后端 API 执行实际创建/重命名，成功后从数据源移除虚拟节点并刷新文件树；取消时直接移除虚拟节点。`editingPath` 通过 `watch` + `nextTick` 自动聚焦并全选输入框文本。

  * **文件树右键菜单**：实现上下文菜单（`@contextmenu.prevent.stop`），根据节点类型（文件/文件夹）和选中状态动态显示菜单项——新建文件、新建文件夹、重命名、删除、复制路径。菜单定位使用绝对坐标，通过 `PointerEvent` 坐标计算确保菜单不超出视口边界。

  * **Agent 面板跨组件通信与引用传递**：在 `AgentPanel.vue` 中实现与 workspace 的双向联动。`watch(pendingAgentPrompt)` 监听 workspace store 中的待发送 prompt，当 `SelectionToolbar` 触发 "Ask Agent" 时自动发送消息并清空 pending 状态。`watch(pendingAgentReference)` 监听待引用的选中文本——收到引用后打开 Agent 侧边栏，将引用文本注入 `ChatInput` 的 reference bar 中显示。reference 文本作为 `sendMessage()` 的第二参数传递，最终通过 POST body 的 `reference` 字段发送到后端（而非 URL 参数，避免长文本 URL 长度限制）。

  * **编辑器上下文感知**：`workspace.ts` 中的 `queueCurrentDocumentContextSync()` 实现 350ms 防抖的编辑器上下文同步。当用户切换文件或修改内容时，通过 `PUT /agent/editor-context/current-document` 告知后端当前正在查看的文件路径、名称、知识库目录、library_id、dirty 状态和打开标签页数量。后端 Agent 可通过 `get_current_viewing_document` 工具获取此信息，实现"基于当前编辑器内容回答问题"的上下文感知对话。

  * **Vditor 编辑器集成（VditorEditor.vue）**：封装 Vditor 实例为 Vue 组件，实现 v-model 双向绑定。Vditor 配置为 `mode: 'wysiwyg'`（所见即所得模式），禁用内置缓存（`cache: { enable: false }`）和内置工具栏（`toolbar: []`），预览配置为 `mode: 'editor'`（仅编辑区，Split 模式由 EditorPane 的独立 MarkdownPreview 实例接管）。通过 `internalUpdate` 守卫标志防止 v-model 的 `watch → setValue → input event → emit` 无限循环。手动接管 Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z 快捷键（`@keydown.capture`），调用 `vditor.undo.undo()` / `vditor.undo.redo()` 内部 API，并在输入法组合输入中（`event.isComposing`）跳过处理。Ctrl+S 触发 save 事件冒泡至 EditorPane 调用 `workspaceStore.saveActiveFile()`。

  * **MarkdownPreview 组件**：实现 `MarkdownPreview.vue` 作为 Split 和 Preview 模式的独立预览面板。使用第二个 Vditor 实例（`mode: 'sv'`，仅预览），通过 `renderVersion` 计数器 + `nextTick` + `requestAnimationFrame` 三阶段防抖队列解决 Vditor 异步渲染竞态——每次内容变化时递增 `renderVersion`，渲染完成后比对版本号，若已过期则丢弃结果。`ensurePreviewPaneIsRenderable` 修复了 Vditor sv 模式中 `element.style.display` 被设为 `'none'` 导致预览不可见的问题（通过 `ResizeObserver` 检测并强制恢复 `display: ''`）。

  * **Edit/Preview/Split 三模式切换**：在 `EditorPane.vue` 中实现分段控制器（Segmented Control）。三种模式——Edit（仅编辑区）、Preview（仅预览）、Split（左右分屏）——通过 `editorMode` 响应式变量驱动。分段控制器使用 `ResizeObserver` 监听容器尺寸变化，实时更新滑动指示器（`.segmented-indicator`）的位置和宽度，指示器通过 `transition: transform 180ms ease, width 180ms ease` 在按钮间平滑滑动。Split 模式下，编辑区和预览区通过 CSS Grid `grid-template-columns: minmax(0, 1fr) minmax(0, 1fr)` 等分面板宽度，两个 Vditor 实例独立运行——编辑区为 wysiwyg 模式，预览区为 sv 模式，避免 Vditor 内置 side-by-side 预览的布局冲突。窄屏（≤920px）自动降级为单列布局。

  * **标签页管理系统**：在 `EditorPane.vue` 中实现类 IDE 标签页栏。每个标签页显示文件名（`tab.title`）、未保存标记（`dirty-dot`，紫色圆点）和关闭按钮（`X` 图标，hover 可见）。标签页通过 `workspaceStore.openTabs` 管理，`activateTab()` 切换活跃标签并加载对应文件内容，`closeTab()` 关闭标签并从 openTabs 数组中移除。标签页栏水平超宽时自动出现细滚动条（`scrollbar-width: thin`）。页面关闭前通过 `beforeunload` 事件检测 `hasDirtyTabs`，若有未保存修改则弹出浏览器原生确认对话框。

  * **文件树↔编辑器联动**：`workspaceStore.selectFile()` 实现完整的文件打开流程——(1) 若文件已打开则直接 `activateTab()`；(2) 若未打开则创建新标签页并异步加载文件内容；(3) 通过 `isSameOrChildPath()`（前缀匹配 + 尾部 `/` 保证目录边界安全）判断是否需要折叠兄弟节点，实现"打开深层文件时自动收起其他顶层目录"的焦点聚焦行为。文件树中的选中状态（`.selected` 类）与编辑器当前活跃标签页的 `selectedPath` 保持同步。

  * **知识图谱可视化（GraphPane.vue + graphRenderer.ts）**：实现基于 Canvas 2D 的知识图谱渲染器。`graphRenderer.ts` 中定义 `EXTENSION_COLORS` Map（7 种文件类型→色彩映射），节点按文件类型着色。图谱节点支持点击交互——点击文件夹节点展开子节点，点击文件节点通过 `openGraphNode` 事件通知 EditorWorkspace 调用 `selectFile()` 打开文件。GraphPane 使用 `defineAsyncComponent` 懒加载，避免图谱渲染逻辑影响编辑器首屏加载速度。力导向布局由 D3-force 驱动节点位置计算。

  * **文件树文件监视与自动刷新**：`FileTreePanel.vue` 中通过 SSE 端点 `/knowledge/files/events` 订阅知识库文件变更事件（创建/修改/删除/重命名），收到事件后自动刷新文件树。同时实现 `ignoreNextTreeEvent` 计数器模式——当操作由当前前端发起时（如重命名、删除、新建），临时忽略下一个匹配的 SSE 事件以避免重复刷新。通过 `rewriteOpenPaths()` 在文件被移动/重命名后自动更新所有已打开标签页的路径引用。

  * **Dashboard 与 Search 视图**：`DashboardView.vue` 提供知识库概览仪表盘（文件统计、索引状态、最近修改等），`SearchPage.vue` 实现全局搜索（文件搜索 + 全文搜索 + 语义搜索），均通过 `defineAsyncComponent` 懒加载。搜索页通过 `Ctrl+Shift+F` 快捷键或 ActivityBar 搜索图标激活。

  * **CommandPalette 命令面板**：`CommandPalette.vue` 实现类 VS Code 命令面板，支持 `Ctrl+K` 快捷键唤起。提供模糊搜索的命令列表（打开文件、切换视图、执行操作等），通过 `workspaceStore.commandPaletteOpen` 控制显示/隐藏。

**四、 遇到的问题与困难**

* **技术问题：**

  * **Vditor wysiwyg 模式下的 v-model 无限循环**：Vditor 的 `input` 回调在 `setValue()` 程序化设置内容时也会触发，导致 `watch(modelValue) → setValue() → input callback → emit('update:modelValue') → watch(modelValue)` 形成死循环。
  * **已尝试的解决方案：** 引入 `internalUpdate` 布尔守卫标志——`input` 回调中先设置 `internalUpdate = true`，`emit` 后再重置为 `false`；`watch` 中检查 `internalUpdate`，若为 true 则跳过 `setValue()` 调用。同时增加了 `instance.getValue() === value` 的快速路径比对，避免相同内容的无效设置。
  * **需要帮助或待解决：** 无。

  * **Vditor Split 模式下的双重实例架构决策**：Vditor 内置的 side-by-side 预览模式（`preview.mode: 'both'`）会在编辑器内部创建预览面板，导致 CSS Grid 布局无法控制预览区宽度和滚动行为。
  * **已尝试的解决方案：** 放弃 Vditor 内置 Split，改为在 EditorPane 的 CSS Grid 中并行运行两个独立 Vditor 实例——Edit 侧 `mode: 'wysiwyg'` + `preview.mode: 'editor'`（不泄露内部预览面板），Preview 侧使用 `MarkdownPreview.vue` 中的 `mode: 'sv'` 实例。两个实例通过共享的 `activeContent` computed property 保持内容同步。这种架构虽然增加了内存开销（双实例），但换来了完全的布局控制和独立的滚动状态。
  * **需要帮助或待解决：** 无。

  * **MarkdownPreview 异步渲染竞态（renderVersion 模式）**：Vditor sv 模式的 `setValue()` 是异步的——连续快速切换文件时，前一次 `setValue()` 的渲染回调可能在后一次调用之后才完成，导致预览面板显示旧文件内容。
  * **已尝试的解决方案：** 实现 `renderVersion` 计数器——每次 `queuePreviewRender()` 调用时递增版本号并捕获当前值，在 `nextTick` + `requestAnimationFrame` 后比对捕获版本号和当前最新版本号，仅当匹配时才执行实际渲染。这确保了只有最新一次请求的内容才会被渲染到预览面板。
  * **需要帮助或待解决：** 无。

  * **Vditor sv 模式预览面板 display:none 问题**：Vditor 在 sv 模式下，当预览面板初始不可见（如从 Edit 模式切换到 Split 模式）时，内部会将 `element.style.display` 设为 `'none'`，导致预览内容不可见。
  * **已尝试的解决方案：** 在 `ensurePreviewPaneIsRenderable()` 中通过 `ResizeObserver` 监听预览容器的尺寸变化，当检测到 `element.style.display === 'none'` 时强制恢复为 `display: ''`，确保 Vditor 内部状态与实际可见性一致。
  * **需要帮助或待解决：** 无。

  * **PointerEvent 拖拽中 transition 导致的视觉抖动**：CSS Grid 列宽的 `transition: grid-template-columns 180ms ease` 在拖拽过程中会导致面板宽度更新滞后于鼠标位置，产生拖拽"粘滞"感。
  * **已尝试的解决方案：** 拖拽开始时通过 `.workspace-page.resizing` 类覆盖 transition 为 `none`，拖拽结束后移除该类恢复动画。同时拖拽期间设置 `user-select: none` 防止文本被意外选中。
  * **需要帮助或待解决：** 无。

  * **TreeNode dragleave 事件子元素冒泡误触发**：拖拽悬停在树节点上时，鼠标在节点文本和图标之间移动会触发 `dragleave` 事件，导致 `.drag-over` 高亮闪烁。
  * **已尝试的解决方案：** 在 `handleRowDragLeave()` 中通过 `relatedTarget` 与 `currentTarget` 的包含关系判断——若 `el.contains(relatedTarget)` 说明鼠标仍在该行内部（只是移动到子元素上），不重置 `dragOver` 状态。只有鼠标真正离开整行时才移除高亮。
  * **需要帮助或待解决：** 无。

  * **SSE 文件监视事件与本地操作的去重（ignoreNextTreeEvent 计数器）**：前端发起的文件操作（创建/重命名/删除）和后端 SSE 推送的文件变更事件之间存在时序竞态——API 响应返回后刷新文件树，但对应的 SSE 事件可能稍后到达，导致重复刷新甚至短暂显示旧状态。
  * **已尝试的解决方案：** 采用 `ignoreNextTreeEvent` 计数器而非布尔值——每次前端发起操作时 `ignoreNextTreeEvent++`，SSE 事件到达时 `ignoreNextTreeEvent--` 并跳过处理。计数器模式确保同时发起多个操作时不会因布尔值覆盖而漏过滤事件。
  * **需要帮助或待解决：** 无。

* **非技术问题：**

  * 无。

* **技术沉淀与可复用经验：**

  * **并发模式范式**：`internalUpdate` 守卫标志（防 v-model 循环）、`renderVersion` 计数器（防异步渲染竞态）、`ignoreNextTreeEvent` 计数器（防 SSE 事件重复）——这三种模式本质上是同一类问题的三种变体（"异步回调/Observer 触发与同步修改之间的因果闭环"），可推广到任何响应式框架的复杂交互场景。
  * **第三方库集成策略**：当框架的"全家桶"能力（Vditor 内置 Side-by-Side、EventSource API、marked 默认输出）与项目定制需求冲突时，"放弃便利性换取完全控制权"的决策模式在两轮实践中均被验证为正确选择。
  * **CSS Grid 动画与交互的协调**：拖拽期间动态禁用 transition + 全局 `user-select: none` 的模式，是解决"动画延迟 vs 交互即时性"矛盾的通用方案。
  * **自定义 MIME 类型拖拽**：`application/x-metaweave-tree-paths` 作为组件间拖拽的数据载体，配合 `files` 优先级检查，实现了内部移动和外部导入的统一处理入口。

**六、 心得体会与学习收获**

* **本周学习到的新知识/技能：**

  * 深入掌握了 Vditor 的双实例架构——wysiwyg 和 sv 两种模式的适用场景、内部 API 差异和异步渲染时序特征。理解了为何"放弃框架内置能力，改用外部编排"有时是更好的架构选择。
  * 掌握了 `renderVersion` 计数器模式在异步渲染竞态中的通用应用——这一模式不仅适用于 Vditor，也可推广到任何"发起异步更新→回调时可能已过期"的场景。
  * 深入理解了 CSS Grid 动画（`transition: grid-template-columns`）与拖拽交互之间的冲突和解决策略——通过动态禁用 transition 实现拖拽即时响应与闲置时平滑动画的兼顾。
  * 掌握了 PointerEvent 在面板拖拽中的最佳实践——在 `window` 上注册 `pointermove`/`pointerup` 而非在触发元素上，确保鼠标移出触发区域后仍能跟踪位置。这一模式与第一周 SSE 流式响应中的"在 `window` 上注册全局事件监听"一脉相承。
  * 学习了自定义 MIME 类型在跨组件拖拽中的应用——`application/x-metaweave-tree-paths` 作为树内拖拽的数据载体，优先级低于 `event.dataTransfer.files`（外部文件拖入），实现了内部移动和外部导入的统一 drop 处理。
  * 实践了 `ignoreNextTreeEvent` 计数器而非布尔值的去重模式——在多操作并发场景下，布尔值会被后续操作覆盖导致过滤失效，计数器则天然支持操作堆叠。
  * 掌握了 `defineAsyncComponent` 在大型组件懒加载中的工程化实践——知识图谱、仪表盘和搜索页三个重型组件按需加载，显著降低了编辑器首屏的 JavaScript 解析时间。
  * 学习了 `ResizeObserver` 在分段控制器指示器自适应中的创新用法——通过监听容器尺寸变化实时更新滑动指示器位置，而非在每次渲染后手动计算。

* **对项目或开发流程的思考：**

  * 本周五项任务（布局 → 文件树 → Agent 集成 → 编辑器 → 知识图谱）的推进顺序本质上是从外到内逐层构建的：(1) 先搭好页面骨架（CSS Grid 布局 + ActivityBar），确定各面板的空间边界；(2) 再实现左侧文件树（数据源），因为编辑器打开文件、标签页管理等核心流程都依赖文件树提供的数据；(3) 然后打通 Agent 跨组件通信（引用传递、上下文感知），因为 Agent 是编辑器的重要消费者；(4) 最后集成编辑器核心（Vditor + 三模式 + 标签页），因为编辑器是前三项的汇聚点——它消费文件树的数据、向 Agent 提供上下文、在 Grid 布局中占据中心区域。这种"骨架→数据→消费者→核心"的递进顺序避免了在核心链路未通的情况下过早实现细节功能。
  * 本周在 Vditor 集成中遇到了多次"框架内置能力不够用"的情况（内置 Split 布局冲突、内置缓存导致内容不同步、内置工具栏无法定制），每次都选择了"绕开框架，自己在外部编排"的方案。这些决策的共性在于：当框架的"全家桶"能力与项目的定制化需求冲突时，放弃便利性换取完全的控制权通常是值得的。这一原则与第一周选择手工 SSE 解析而非 EventSource API 的思路一致——框架封装了简单场景，但复杂场景需要更底层的控制。
  * 文件树作为编辑器的数据主干，其交互设计（拖拽移动、内联编辑、右键菜单、多选操作）的复杂度远超预期。`insertDraftNode` 虚拟节点模式在不污染真实数据源的前提下实现了乐观 UI 更新，是一种比"先调 API 再刷新树"更流畅的用户体验策略。

* **自我改进方面：**

  * Vditor 集成花费的时间超出了预估（原计划 2 天，实际约 2.5 天），主要额外时间花在解决异步渲染竞态和双实例协作问题上。后续评估第三方库集成工时时应预留更多"踩坑缓冲"，尤其是涉及富文本编辑器和自定义渲染管线的场景。
  * 文件树拖拽系统和内联编辑的交互细节应该在设计阶段更早考虑——`dragleave` 冒泡、`insertDraftNode` 生命周期等问题如果在编码前画出交互状态机，可以减少调试时间。
  * 本周与后端 Agent 的协作（编辑器上下文感知、SSE 文件监视）暴露了前后端对"实时性"理解的差异——前端期望毫秒级响应，后端部分操作（如向量重建）是秒级异步任务。后续应在 API 设计阶段明确各端点的响应时间预期和状态同步策略。
